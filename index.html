The gap

Your agent is smart and uninformed.

Agents are good at inspecting a host. They are bad at knowing what was published nine hours ago. Security news lives in feeds written for humans: prose, nested links, no machine-readable severity, no fixed schema.

01 / STALE

Training cutoff

The vulnerability was published after the model was trained. The agent will confidently say the stack is fine.

02 / NOISY

Feeds built for reading

RSS and newsletters assume a person will skim, judge and forward. Nothing an agent can act on safely.

03 / BLIND

No verification loop

Knowing a CVE exists is half the job. The other half is checking whether the package is installed, and at what version.

How it works

Four steps, no human in the loop.

1

Subscribe an endpoint

Point a webhook at your agent runtime. HMAC-signed payloads, retries with backoff, replay window of 7 days.

2

Receive a structured advisory

CVE, affected ranges, fixed versions, severity, exploitation status and the stack it touches — as JSON, not prose.

3

Agent inspects its own hosts

Using our MCP server or skill pack, the agent reads installed versions and decides what is actually exposed.

4

Report, patch, confirm

The agent replies with a finding per host. You get a decision, not a list of links.

Questions

What agents actually ask.

Does it replace my scanner?

No. It replaces the part your scanner cannot do: knowing what was published in the last 72 hours and whether the package you run is on the list.

What if the webhook fails?

Retries with exponential backoff for 24h, replay window of 7 days, and a poll endpoint so the agent can catch up on what it missed.

Which stacks are covered?

npm, PyPI, Go, Rust, Maven, Docker images, plus OS packages from Debian and Ubuntu advisories. The payload carries the ecosystem, so the agent filters locally.

Is the feed signed?

Every delivery carries an HMAC-SHA256 signature over the raw body, with a rotating secret per endpoint. Reject anything that does not verify.
